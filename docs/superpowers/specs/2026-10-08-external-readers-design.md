# MangaWeb与WebDAV漫画的灰度／全刷接入设计（待审核）

日期：2026-10-08。用户已确认方案A：灰度与全刷核心共用，三个插件小幅升级；两个内置阅读器都要实际支持这两项功能，并能在各自插件内开启、关闭，默认关闭。本文件是实现前的临时设计书，尚未修改产品或发布兼容版。

## 当前事实与目标

固定源码：

- GrayDither 0.2.0：已发布，当前main为39b6618eca3263efd5b560a0e93dd9e45a03285d。只接入原生ReaderUI的MuPDF CBZ／CBR与页面事件。
- MangaWeb 0.8.83：[aa7698e3439a37c4cb600103039f3f7cc6c65925](https://github.com/bailigebai/mangaweb.koplugin/tree/aa7698e3439a37c4cb600103039f3f7cc6c65925)。内置图片阅读器使用自己的ImageWidget和模态Page。
- WebDAV漫画0.4.15：[57151d385d6cbd71e1fce4cb92864f0507bf1aab](https://github.com/bailigebai/webdavmanga.koplugin/tree/57151d385d6cbd71e1fce4cb92864f0507bf1aab)。内置图片阅读器使用自己的ImageWidget和非模态ReaderWidget。
- KOReader：[646b2e39e24a899016d38ef6dc47e3f7c429c8ba](https://github.com/koreader/koreader/tree/646b2e39e24a899016d38ef6dc47e3f7c429c8ba)。PluginLoader提供getPluginInstance，ImageWidget最后完成缩放、alpha合成与夜间反色。

两个内置阅读器都不调用现有灰度包装的Document.drawPage，也不发送其依赖的PageUpdate／PosUpdate，所以现有0.2.0只证明可共存，尚未实现内置阅读的灰度和额外全刷。

目标：三插件启用后，用户可以在MangaWeb或WebDAV漫画阅读设置中分别操作灰度与全刷。关闭或缺少灰度插件时继续使用源阅读器的既有路径；功能开启后只处理当前可见正文，不处理书架、封面、设置、气泡或按钮。

## 三种方案与已确认决定

| 方案 | 代价与结果 |
|---|---|
| A：共用核心，源阅读器可选接入（已选） | 三插件升级；算法及刷新控制只维护一份，源插件负责自身画面和事件 |
| B：仅灰度插件挂接两个阅读器内部类 | 安装改动少；耦合私有实现和加载顺序，源插件更新容易破坏接入 |
| C：两阅读器各复制算法与刷新器 | 各自可独立运行；重复维护与行为分叉，不符合避免技术债的要求 |

不构建通用插件框架，不引入原生库或设备侧依赖。本次只支持两个已核对的阅读器和原有原生文档功能。

## 用户设置与默认行为

1. 两阅读器各有“灰度抖动”与“自动全刷”开关，分别保存，缺少设置时均为false。灰度与自动全刷可独立使用。
2. 三插件升级首次接入时，现有全局灰度／全刷值不会自动开启两个内置阅读器。某个阅读器开启也不改变另一个阅读器或原生书籍的设置。
3. 源插件保存自己的功能偏好；公共核心复用验证与菜单构建规则，避免在两边复制刷新控制器。刷新参数仍采用原有约束：间隔1～50次、默认5，原生／黑白辅助，保持0.10～1.00秒、默认0.30秒。
4. 阅读设置提供手动全刷；它是用户主动请求，与自动开关分开。没有可用共享服务时说明需要安装并启用灰度插件，源阅读器仍可阅读。
5. 关闭灰度后恢复原绘制；关闭自动全刷后立即取消其待执行或正在执行的辅助流程。偏好持久保存，重启后沿用用户选择。

## 模块与接入边界

### GrayDither

- 可安全在FileManager加载；原生ReaderUI的文档生命周期继续使用现有pipeline，不把自定义图片reader伪装成MuPDF文档。
- 提供一个可选图片阅读会话入口。源插件通过官方PluginLoader:getPluginInstance("graydither")获取启用实例，并检查入口能力；不主动加载已禁用插件。
- 图像处理、会话归属、刷新控制和设置校验集中维护。每个外部阅读会话持有自己的owner、偏好提供器、页面标识和取消代次。
- 会话关闭、插件停用或宿主销毁时清理全部待执行任务与覆盖层；清理可重复调用。

### 两个源阅读器

- 各自在自己创建的正文ImageWidget实例上接入，不覆盖全局ImageWidget或UIManager。
- 传递当前真实顶层阅读窗口、可见正文是否就绪、逻辑屏标识和生命周期事件。
- 复用现有设置保存、图片增强与进度记录流程；新开关不进入预处理缓存编号，不触发对下载原图的修改。
- 无服务、服务不支持或异常时恢复原显示路径，并保留错误状态供用户查看。已有阅读授权、网络请求与下载流程沿用源插件机制。

## 图像处理合同

处理顺序：源阅读器的亮度／去灰等处理 → 原ImageWidget最终缩放、裁剪、alpha合成及反色语义 → 私有正文区域的FS灰度处理 → 写回当前屏幕图像区域。

- 缓冲只覆盖实际图片绘制区域，使用已归一化BB8或RGB32；限制沿用8192边长／8 Mi像素，未知格式安全显示原图。
- 共享原图、viewport、预加载缓冲及PNG缓存均不被修改或释放；私有缓冲由公共核心负责释放。
- 用局部目标绘制适配保留ImageWidget语义，并把其软件抖动调用转为相同的普通合成调用，避免先进行宿主软件量化再进行FS；不改变全局Screen标记，不用is_icon规避抖动。
- 只更改当前控件的实例绘制入口，退出时按归属还原，保留后来安装的其他包装。
- 不按每次重绘重复改变已处理缓存；每次处理的输入来自原显示结果。保留夜间、透明、裁剪、旋转和未绘制背景。

## 翻屏计数与刷新合同

- 首屏建立基准，实际可见正文成功绘制新逻辑屏后计数。同一逻辑屏重绘、预加载、进度更新、加载／错误页和设置不计数。
- 标识包含会话代次以及源阅读器实际的图片、分片、平移、长条位置或分格状态；把标识变化转换为会话内递增整数，复用现有Refresh控制器。
- MangaWeb owner为Adapter.reader_widget。设置嵌入同一Page，必须额外拒绝embedded_controls、loading、error和released状态。
- WebDAV owner为shell.widget，并要求current_model.kind为page。普通、适宽、左右分片、象限、长条与分格都从最终正文控件统一接入，避免只覆盖_display_segment。
- 两边设置、遮挡、加载／错误、关闭、休眠／恢复、旋转与尺寸事件都能暂停或取消待执行流程；恢复时以当前可见屏重建基准。
- WebDAV在共享自动刷新实际生效时，临时由共同控制器管理额外刷新，避免旧“每页全刷”和黑白辅助叠加；旧偏好保留。关闭、无服务或失败时恢复源策略。源翻页动画在接管刷新期间停用，避免与辅助流程交错。
- 原生方式请求宿主full；辅助方式复用现有可取消黑／白／恢复流程。没有承诺厂商驱动物理波形或残影效果。

## 分阶段验收

1. 公共核心：默认不处理／不排任务，启用后私有区域输出正确；真实ImageWidget合同保留alpha、夜间、背景和缓存，错误恢复与释放通过。
2. 源阅读器：开关分别保存且默认false，服务缺失／停用不影响原阅读；三个插件实例归属及切换读者无遗留任务。
3. 阅读模式：当前真实实现支持的普通／分片／适宽／象限／长条／分格路径接入；新逻辑屏计数，重复绘制、设置、预加载不计数，原全刷不叠加。
4. 生命周期：关页、设置、加载失败、快速翻屏、休眠、恢复、旋转与尺寸变化，覆盖层及回调不残留；关闭开关立即恢复。
5. 独立审查与安装包：完整相关套件、真实宿主合同、最终解压包检查；升级说明、版本／标签／ZIP一致，再准备三个可供审核的发布结果。

## 明确的边界

本地合同及测试不是Kindle／Android／鸿蒙实机验证。保持现有MangaWeb分片／平移绘制能力和WebDAV设备旋转布局能力的事实边界，不把接入工作扩大为源阅读器功能重写。性能、峰值内存、光学灰度、残影和能耗需在实际设备对照；鸿蒙NEXT仍没有HAP。

当前原灰度完整68项检查通过，8个Lua文件编译通过。两源插件只读审查已固定版本，兼容功能尚未实现；后续证据分别记录。
